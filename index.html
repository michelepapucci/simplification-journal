Simplification data explorer

READ-IT distributions and linguistic profiles of the original–simplified pairs used to train and test the readability-controlled simplification models, taken from the Wikipedia part of IMPaCTS. The analyses are those of Papucci, Venturi & Dell’Orletta (CLiC-it 2025), re-run on each dataset and broken down by control token.

Dataset

How each dataset was built

Every dataset, in the order it was built: what it contains, how the control tokens are given, why it was built, and whether it worked. A dataset name switches the explorer below to it. Part 2 holds the numbers. A range like “70–80” means requests for level 70, and the value is the mean READ-IT the outputs reach.

One token per example
the CLiC-it format: each pair is repeated once per dimension, each time with that dimension’s level, e.g. <|readability_syntax_70|>.
Three tokens per example
our format: each pair appears once, with a target for every dimension, either a level or any, e.g. <|readability_base_60|><|readability_lexical_any|><|readability_syntax_70|>. During training each set target is replaced by any with probability 0.3.

v7the CLiC-it format, plus combined examples v3’s pairs plus 1,031 identity pairs with syntax and base targets: 267,390 training examples. Part 2

Model generation analysis

How the v5 and v7 models use each of their three tokens, with the same sentences under every request: control token interpretability.

  • No model of ours controls READ-IT better than the CLiC-it 2026 0.6B overall. The v7 model comes closest: about level on base and lexical, ahead on syntax over all requests (RMSE 25.8 against 26.9), and 1.2 points of RMSE behind it at syntax 60–80. v5 is ahead on syntax at the top of the scale, but copies more.
  • Giving the model the original’s own levels (source tokens) changes nothing measurable.
  • Lexical is still not controllable: requests from 0 to 30 all land near 40. Almost every lexical target in v1 is one level below the original.
  • Dataset v2 adds 11,752 pairs with lexical drops of two levels or more, and lexical still does not follow the request: requests from 0 to 20 land at 38–39, and within an original requested and achieved lexical are unrelated (Spearman 0.06). Base, syntax and the joint evaluation are unchanged.
  • The v1 and v2 models always simplify (at most 4% copies), so they overshoot mild requests. The CLiC-it model’s edits at the top levels are milder, with or without its copies: at base 60–80 its RMSE is 18.9 (18.8 without copies) against about 21.
  • Dataset v3 gives the light edits a token: a pair whose simplification stays in the original’s base or syntax level gets that level as target. Base requests at 70–80 then land at 66.9 instead of 62.3, and base RMSE at 60–80 falls to 19.8, without copying more (1.0% copies). Syntax does not move: a syntax drop needs 17.6 points to be labelled, more than a level, so the one-level drops it would learn from are almost all left free.
  • Dataset v4 labels those syntax drops too, so every pair whose syntax did not rise has a syntax target. Syntax requests at 70–80 still land at 57.3 (v3: 56.6; CLiC-it: 68.1). In this data a simplification of an original at syntax 80 is an equally heavy edit whether its score lands at 80, 70, 60 or 50, so the labels have nothing distinct to teach. Over all syntax requests v4 is ahead of the CLiC-it model (RMSE 26.0 against 26.9, 17.9% inside against 15.5%, 1.6% copies against 5.7%). Base loses v3’s gain (60.6 at 70–80): syntax “any” used to mark the pairs whose syntax barely changed, and no longer does.
  • Dataset v5 adds 989 identity pairs (the original as its own simplification) at syntax 60–90, at the CLiC-it 2026 data’s share. Syntax at the top moves past the CLiC-it model: requests at 70–80 land at 73.7 (CLiC-it: 68.1), RMSE at 60–80 falls to 22.4 (23.2) and ρ within rises to 0.59 (0.50). But half the outputs at 70–80 are copies, twice the CLiC-it model’s share.
  • Dataset v6 has 240 identity pairs instead, as many as give the CLiC-it data’s share among training examples that show the syntax token alone. At that dose the model barely copies (6.2% at the highest syntax request; CLiC-it: 22.1%), and syntax at the top does not move (54.8 at 70–80). The model learns a syntax token from every example that shows it, with or without other tokens: by that measure, v5 had 1.2 times the CLiC-it data’s share of identity pairs and v6 0.4 times. In this run, a fifth of the outputs at base request 0 are near-copies, which raises base RMSE from 20.8 to 24.3; without that request, base is v3’s.
  • Dataset v7 is v3 in the CLiC-it format: one example per token, plus one combined example per pair. It has 1,031 identity pairs, at the CLiC-it data’s share among all examples that show each syntax token.
    • Copies: the model copies at the CLiC-it model’s rate (21.0% at the highest syntax request; CLiC-it: 22.1%).
    • Syntax at the top: requests at 70–80 land at 65.7 (v3: 56.6; CLiC-it: 68.1).
    • Goals: three of the four syntax goal conditions are met, and base at 70–80 lands at 68.3. RMSE at 60–80 is still 24.4 against 23.2, because the outputs that are not copies are slightly heavier edits.
    • Lexical: its share inside rose to 14.9% (CLiC-it: 14.4%) with the same labels.
    • Overfitting? Validation loss rose from step 2,500 to the end of the 12,534 steps. Trained for one epoch (lowest validation loss 0.705), the model does worse: at syntax request 70 its outputs that are not copies land at 58.9 (three epochs: 59.8), and it copies at mild requests too (base copies 4.6% against 1.5%; base RMSE 23.1). The heavy edits come from the format, and the extra epochs teach the model when to copy.
    • How the tokens are used (interpretability): held requests now work for base, unlike in v5, but the three tokens are still one “simplify” dial, more so than v5’s.
  • With all three dimensions requested, 3–5% of outputs land inside all three levels.
